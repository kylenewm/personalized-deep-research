Stage Details

1 Batched Pointer Extraction pointer_extract.py
Input: Sources batched (10-12 per batch)
LLM outputs: {source_id, keywords[], context}
Code does: Keyword matching to find actual text
Quality filter: Rejects tables, metadata, fragments

Key insight: Single keywords match better than phrases. "Biden", "October", "2023" works better than "October 2023".
↓
2 Arranger (Grouping + Curation) pipeline_v2.py
Input: All verified extractions
LLM does: Groups facts by theme (4-6 themes)
Curation: Drops 40-60% redundant/off-topic facts
Output: Theme groups with fact IDs
↓
3 Per-Theme Synthesis pipeline_v2.py
For each theme:
• LLM writes intro (2-3 sentences)
• LLM writes transitions between facts
• Facts themselves are LOCKED (code-extracted text)

Assembly: Executive summary + themed sections + analysis + conclusion

Quality Controls

1 Per-source dedup Max 1 extraction per source URL
2 Cross-source dedup Jaccard similarity > 0.4 = duplicate
3 Quality filter Rejects: tables (| | |), metadata, low alpha (<50%), truncated, markdown artifacts
4 Substring verification LLM cleanup must be substring of original. If not, keep original.

Anti-Hallucination Layers

Multiple defense layers prevent fabricated information:

1 Grounding Prompts All prompts include: "ONLY include information from search results. DO NOT invent facts. Every claim MUST have citation."
2 Council Fact-Checking validate_findings checks for: fabricated names, impossible dates, uncited claims, suspicious statistics
3 Deterministic Extraction extract_evidence uses spacy chunking / regex - NO LLM calls. Can't hallucinate.
4 Deterministic Verification verify_evidence: strict substring check + fuzzy Jaccard (0.8 threshold). NO LLM calls.
5 Verified Findings Lock Separate LLM call with selector-only prompt. Can ONLY use PASS-verified quotes. Post-check enforces immutability.
6 Claim Verification (Optional) Post-report: embeddings match claims to sources, logs warnings for unsupported claims
